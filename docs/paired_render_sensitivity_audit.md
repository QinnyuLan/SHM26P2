## 数值与预测合同

有标注TRAIN按名称排序，取`floor(i*258/15)`的16张。16张均以原生K、w2c_original及完整网格渲染；相机、模型和证据不更新。每张的十个干预按固定顺序为：

1. `raw_render`：原始float RGB R，直接传原head，不clamp、不uint8化。
2. `paired_025`：`.75 R+.25 I`，不clip。
3. `paired_050`：`.5 R+.5 I`，不clip。
4. `real_rgb`：v2准备数据里的真实TRAIN RGB，OpenCV BGR→RGB后除255。
5. `roll_plus_025`：`clip(R+.25 roll(I-R, (+H//3,+W//3)),0,1)`。
6. `roll_plus_050`：同一roll，系数.5。
7. `roll_minus_025`：负向`-(H//3),-(W//3)`roll，系数.25。
8. `roll_minus_050`：同一负向roll，系数.5。
9. `next_camera_050`：16名单中循环下一相机的真实/渲染残差，逐通道RMS缩放到当前相机残差，再`.5`加入R并clip。源通道RMS为0时输出零扰动并明确记录，不能声称这一通道也完成幅度匹配。
10. `affine_rgb`：不读GT，仅用真实/渲染RGB在固定`[::16,::16]`像素格拟合逐通道gain/bias，完整图应用后clip；constant输入通道退回均值offset。

R可以越界；所有候选均记录clip前后RMS、逐通道RMS、像素/通道越界比例、clip比例及像素RMS分位数。每个32×32块（含不完整边块）记录局部clip/RMS和输出JS、中心化log-probability MSE。roll只在clip之前保留残差频谱和范数，相机错配只匹配RMS；这些对照不保证离流形程度相同。尤其raw/half不clip而三个控制clip会引入非对称性，统计它不等于已经消除了混淆。若该混淆明显，不按结果另挑一个更有利版本；本次结果写为不能识别。

所有干预调用同一个原refiner的forward，F/depth/alpha/p3d完整固定，让现有`evidence_tensor`按新的RGB自动重算RGB梯度通道。`p(R)`必须和独立原生`scene.render(refine=True)`的概率数组逐位一致；证据render为`refine=False`，与原生render的RGB、深度、alpha、features及prior也逐位比较。故总预算为32次场render和176次头前向，仍只评价十个预定干预。

环形处理相邻相机，最多保留两份render证据和首图残差；当前相机十份FP32概率只在RAM中暂存供GT解码之后评分，不落磁盘，不导出350视图缓存。每张所有十份预测完成后才解码其GT/valid。准备计划时允许先读这些文件的字节计算SHA，这不等于将像素标签输入预测器。真实TRAIN RGB在此确实是干预输入，不能将任何干预精度写成camera-only成绩。

## 统计和来源

每个方法保存全图、GT 2px边界、非边界、baseline正确/错误、两向roll接缝±2px带并集的计数、CM和五类分组。GT未知/无效像素排除。margin=`log p(GT)-max_other log p(other)`；NLL=`-log p(GT)`，FP32按类归一化、log epsilon=1e-7。先在每视图出现的GT类内等权，再对相机等权；另保留像素加权汇总，不能混淆两个估量。正margin增量和正NLL gain均表示改善，paired表的原始NLL candidate−reference则越负越好。

固定5000次、seed20260926的相机配对bootstrap报告所有方法相对raw、以及paired_050相对两个roll_050、next_camera_050、affine_rgb。all5百分点区间是次要统计。affine解释量报告paired−affine的margin/NLL gain及描述性比值；比值可负或大于1，分母绝对值≤1e-8时NA，它不是因果中介比例。

锁定plan会绑定16张RGB/GT/valid、manifest、checkpoint、训练/official回执与对应metrics、uv.lock、脚本和完整package快照SHA；运行前后复核全部输入与源码，实际import路径必须位于快照。执行前后逐tensor核验整个scene不变，并核验scene元数据、传入相机以及每次head的证据不变。

## 执行流程和预算

CPU准备pending草案（不会读取last.pt）：

```bash
CUDA_VISIBLE_DEVICES='' uv run python scripts/make_paired_render_sensitivity_plan.py
```

之后必须先完成v2语义和共同official评价。root确认具体official回执后，才运行CPU锁定步骤；显式传`--official-receipt`，其余默认路径见`--help`。生成器拒绝覆盖已有草案、计划和源码快照。

```bash
CUDA_VISIBLE_DEVICES='' uv run python scripts/make_paired_render_sensitivity_plan.py \
  --lock --official-receipt <completed-v2-official-execution_receipt.json>
```

锁定计划提交root复核后，再用**plan内的source_snapshot**显式设置PYTHONPATH执行runner；不能继续读取可变main package。运行窗口从load_scene开始，到16视图预测/CPU评分完成预算300秒；每次render/head及每视图后协作式检查，超时失败并保留receipt，不自动续跑/更改预算。单次render/评分不可被该Python检查抢占，因此这不是操作级实时截止保证。之后只有小规模CM/标量bootstrap和JSON写盘，不再GPU推理。

不创建概率缓存、图像恢复模型或训练optimizer。每相机概率暂存约249MiB，完整JSON主要是固定块统计，预计低于100MiB，最终以实际字节记录为准。单CPU合成1320×989网格、十个方法的完整评分实测约2.87秒，输入/输出局部统计约2.75秒，紧凑JSON的16视图统计估计约41.5MiB；仅作为本机脚本开销参考，不是GPU时延或真实数据性能。

15项CPU回归通过，覆盖raw越界、不裁剪半路径、roll频谱/相机RMS、affine固定采样、局部clip记录、双向翻类/未知像素、类与相机等权、GT解码顺序、RGB梯度重算、证据修改拒绝、超时、pending计划不能执行/读checkpoint、completed回执和profile绑定、锁定输入路径及完整源文件集合。Ruff通过；下文记录随后一次获准运行的真实GPU诊断。

**结论：本有限TRAIN内诊断不支持继续投入配对残差方向的四臂训练。** 不实现02训练，不调t/roll/JS系数，不转用VAL真实RGB检验或挽救假设。这个结果既不是“头完全不看RGB”，也不否定所有域适配/鲁棒训练；它仅说明本固定v2模型与控制下，没有识别出足以支持后续投入的空间配对特异收益。16视角来自模型已拟合的259标签TRAIN，精度饱和；视角bootstrap不能提供独立场景泛化结论。真实图补回细节、render域头的OOD响应和控制剪裁差异仍然存在，不能以标准一致性正则重新命名为已成立创新。
