# TRAIN 标签往返与当前错误交集：固定 CPU 结果

该离散目标不一致确实存在，但本次证据不足以把它视为主要精度瓶颈，也不放行新的训练。固定16个已参与拟合的 TRAIN 视角，在完整有效插值支持内，标签往返差异仅占像素的 **0.018109%**；即便理想纠正与当前错误相交的全部像素，五类 mIoU 也只增加 **0.066774 个百分点**。这些是诊断支持内指标，不是官方全图指标、VAL 收益或模型精度上限。

执行采用冻结[协议](semantic_target_warp_protocol.md)，一次 CPU 自然 exit0，内部7.687秒、包含启动外层8.702秒。只加载16份已保存 H3 S 概率、32次 prepared mask/valid PNG 和16份 TRAIN 原标注；0模型加载、0渲染、0优化、0GPU初始化、0VAL读取。原计划、源码和输入前后 SHA 全部相同。

原图已知像素20,887,680；完整已知双线性支持20,812,416（99.639673%），剔除75,264个支持不完整/无效像素。以下 pooled 指标先汇总混淆矩阵再计算，未平均逐图 IoU。

拉索二值 GT 的固定3像素边界带含371,056个支持像素、16,429个当前错误和1,443个交集错误（8.783249%）；该带包括边界两侧，不能把其全部错误称为“GT拉索错误”。GT为拉索的1,137个往返差异及666个交集都在此带；带外仍有238个GT拉索错误，交集为0。其余四类边界/补集和逐视角完整 CM 保留于结果 JSON。

逐视角等权 oracle mIoU 增量为+0.098034pp，与上表 pooled +0.066774pp 是两个不同统计量。16图均按预定名单报告，没有按视角、类别或半径选择结果。标签差异与错误重叠不证明训练目标导致了错误；oracle 用 GT 直接替换，不能部署，也未检验参数更新能实现该增量。
