# 固定多场 RGB 与 H3 语义融合：前瞻性协议

2026-09-27，执行前登记。上一轮仅评估新组合 RGB 上的纯 H+ 读出，尚未检验原 H3 语义分支的互补性。本轮零训练，固定已有端点和 0.5 概率权重；这是增加渲染成本的工程组合，不作为学术创新。

## 四个机制对照与一个工程控制

所有分支均使用同一个旧 H3 cross 场的 refined 语义概率。禁止用旧 hard mask 合成新 mask。

| 分支 | 交付 RGB | H+ 输入 | 教师端点 |
|---|---|---|---|
| A：既有系统复现 | H3 本场原图 RGB | H3 原生 legacy 覆盖画布的量化 RGB | 历史 00f5 EMA |
| B：新 RGB、冻结教师 | 1M 与 MCMC 原图 uint8 RGB 各 0.5 | 新 RGB 经既定 original→legacy 适配器 | 历史 00f5 EMA |
| C：同预算旧域控制 | 与 B 相同 | 与 B 相同 | selected 固定 2k last EMA |
| D：匹配新域候选 | 与 B 相同 | 与 B 相同 | composite 固定 2k last EMA |
| E：只升级交付 RGB | 与 B 相同 | 与 A 相同 | 历史 00f5 EMA |

E 在执行前单独固定：使用本次实际重新推理的 A 软概率融合结果生成语义 mask，同时交付本次两新场渲染的 RGB 均值。它无需新增教师前向；不得读取旧 mask 冒充新预测。这个高成本 camera-only 系统直接检验已知 RGB 收益能否在不改变原语义函数的条件下落地，不属于 D 的域适配假设。E 保存独立 RGB/mask 和完整来源，不能把未经实际运行的两个成绩直接拼为联合结果。

三个教师共享 ModelScope DINOv3 H+/16 冻结主干，均使用原 tile768/stride512/flip/context0.25/short-side768。C/D 已在前一轮自然完成，同一初始化、1000 real + 1000 rendered 更新和逐步增强/RNG 核验保持不变；不重训、选 best 或扫组合比例。

H3 保持 `legacy_mixed_v1`；1M/MCMC 各自保持 `colmap_corner_v2`。先分别映射为同一原始相机的 uint8 RGB，再用 float32 算术均值及 ties-to-even 量化组合。新 RGB 通过已使用的 OpenCV `initUndistortRectifyMap`、`INTER_LINEAR`、零边界移到 legacy 画布，不改标签或重标 checkpoint profile。H3 与教师的 **soft probabilities 在同一 legacy 画布各乘 0.5 后相加**，再按原 legacy 映射到原图，最后 argmax。

## 实际运行与复现检查

固定原有 50 个相机 / 41 个有语义标注视图、原图 1320×989、原始姿态和畸变参数。预测只接收相机白名单；不输入真实验证照片、annotation 或 valid map。

- 三个场各实际渲染 50 次，共 150 次 scene 调用；这些调用可能也计算未使用的语义输出，不能写作仅 150 次 raster。
- 各场交付 RGB 与既有对应 PNG 逐像素一致，组合 RGB 与已有新组合逐字节一致后，才可继承已绑定的逐图 PSNR/SSIM/LPIPS；本轮不重读 RGB GT 或重算 LPIPS。
- A 的 50 张新生成 mask 必须精确复现旧 selected 的 mask。B/C/D 教师的独立原图 argmax 必须分别精确复现此前对应纯教师 mask，确保融合变化没有暗中修改教师路径。
- 保存 H3 与四臂教师的 float32 软概率，绑定哈希，供独立 CPU 从 soft blend、warp 到 argmax 重算。缓存放数据盘。
- 四臂和 E 共 250 张交付 mask 全部完成并记录后，才读取 41 个原图标注并评分。四臂有 200 次独立语义推理组合，E 复用本次 A 的软融合结果，不另计教师前向；不继承旧 mask。
- 冻结执行脚本、包源码、依赖版本、端点及输入 SHA；使用已有 uv 虚拟环境。内部 570 秒、外部 600 秒，无自动重试。环境失败与指标失败分开记录。
- 允许普通 G 桌面进程及 `/proc/<pid>/exe` 确认是 RustDesk 的 C 进程，其他计算进程拒绝；不终止用户桌面应用。计时明确非独占 GPU，记录实际渲染、模型加载、预测与评分范围。

## 比较、采纳与解释

主候选固定 D；比较 D−A、D−B、D−C，按同相机 5000 次 bootstrap、seed 20260926。A 必须复现历史完整系统，C 是适配域因果比较的同预算控制，B 则用于量化额外适配的总体影响。不得看到结果后把更好的 B/C 改称主候选。

系统采纳沿用四项 RGB 门（相对已绑定 SSIM-fixed 500k：PSNR 至少 +0.15 dB、配对区间下界 >0、SSIM 不降、LPIPS 不升），并要求相对 A：全类 mIoU 至少 +0.20 个百分点、配对 95% 区间下界 >0、索 IoU 不低于 −0.10 个百分点。域匹配证据独立要求 D−C 全类 mIoU 至少 +0.20 个百分点且区间下界 >0；不得用 D−B 代替。报告全部端点、全部类别及失败项，不降低门槛或扫教师权重。

E 不使用上述 D 的机制门，不得写作 D 获得通过。E 的工程验证要求四项既定 RGB 门通过、全部 50 张 E mask 与本次 A 及历史 selected 字节一致、全部 E RGB 与本次新均值及历史新组合字节一致。完整报告 E−A 和 E−已有本地 SEM386-style Swin-L 参考的相机配对差值；后者仍是不同容量/训练历史/TTA 的完整系统比较，不等于精确重现同学方法。E 在固定开发集上可具有 RGB 提升且语义函数不变的性质，但不保证新场景、盲测或跨模态几何一致。

多场系统需要三套 Gaussian 场和一个 H+ 教师，不能声称仍是单一共享几何。H3 自身 RGB/语义共享几何，但交付 RGB 来自另外两场。教师融合仍包含二维精修，不能将最终精度归给原生三维类别。这一成本和方法差异在论文与比较中必须明确。

开发集已反复用于研究，bootstrap 只描述固定开发集上的视图抽样，不包含模型选择、训练随机种子及跨桥泛化。新 RGB 的成员也来自已有开发结果，不是盲测。缺少同学 Dev30 清单与相同 RGB 留出端点，仍不得据此宣称公平超过其精确方案。
