# 与 `project_progress_20260918` 的可复核对照

## 先区分两种协议

同学目录 `project_progress_20260918/data/content.json` 记录的是全量拟合结果：RGB148 使用 RGB 全量条目，SEM380 使用 RGB148+SEM380 的 300 个标注视角。F 的正式采用门则是固定 50 个留出相机、其中 41 个有 JSON 标注，且预测全部落盘后才读取真值。因此下面同时保留两种数字，不把全量拟合差异写成未见视角泛化。

## 全量拟合对照

为便于直接核对，F bundle 另外对 300 个有标注相机生成预测，再以同一官方原始像素网格做 CPU 评分。该导出阶段读取目标真值数为 0；评分阶段才读取 300 张 mask 和 RGB。结果：

| 条目 | RGB PSNR (dB) | RGB SSIM | 五类 mIoU |
|---|---:|---:|---:|
| `project_progress_20260918` RGB148 + SEM380 | 23.305737 | .896586 | 95.306455% |
| F（300 有标注视角全量对照） | **31.095728** | .876151 | **96.590043%** |
| F − 参考 | **+7.789991** | −.020436 | **+1.283588 pp** |

F 的全量 mIoU 和 PSNR 明显高于目录中对应条目；SSIM 仍低于参考。该全量评分没有计算 LPIPS，不能据此宣称三个 RGB 指标全面领先。复核回执为 `/mnt/data/SHM2026/runs/f_all300_evaluation_v1/all300_score.json` 与 `all300_cpu_review.json`，预测目录为同一运行目录下的 `render/`。

## 正式留出结果

F 的采用结果仍以 50/41 协议为准：PSNR **30.236593 dB**、SSIM **.875024**、LPIPS **.259300**、mIoU **95.109016%**。相对可复核的本地 SEM386-style Swin-L 留出参考，PSNR 提高 **.835644 dB**，mIoU 提高 **.790633 pp**；相对同学全量 RGB148 的 SSIM/LPIPS 数字则不能做泛化结论，因为训练历史和视角划分不同。

后续报告应优先引用正式留出结果，并把全量表作为“同学报告数字的工程复核对照”。F 维持当前部署与 DINOv3 H+ 语义路径不变。
