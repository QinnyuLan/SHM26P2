# H2：固定教师下的位置可靠性融合控制实验

本实验只检验同一桥梁、同一学生检查点和同一教师导出下，投影协方差采样是否比固定范围采样提供额外价值。生成器为 `scripts/make_h2_configs.py`，只读取检查点元数据、写新配置和计划，不启动训练，不修改选中模型、伪标签或核心源码。

## 1. 四组对照

| 文件名 | 直接 raw KL | 最终伪标签 KL | 多视图点 KD | 采样范围 |
|---|---:|---:|---:|---|
| `00_gt_continuation.yaml` | 0 | 0 | 0 | 不融合 |
| `01_teacher_no_fusion.yaml` | 0 | 0.1 | 0 | 不融合 |
| `02_teacher_fixed_sampling.yaml` | 0 | 0.1 | 0.05（默认） | 固定 `0.25 I`，九点采样 |
| `03_teacher_projection_sampling.yaml` | 0 | 0.1 | 相同0.05 | 相机/点位置协方差传播，九点采样 |

默认生成四组；`--without-gt-control` 生成后三组，但此时不能量化教师相对无教师续训的增量。`--fusion-weight` 可在运行前指定正数，两组融合必须一致；不能事后为不同采样方法选择各自最好的权重。

**H2 核心比较是03对02**。02对01衡量固定范围融合的增量；01对00衡量最终伪标签监督的增量。固定范围不是中心点投影；本实验也没有单独去掉可见性、空间一致性或多视图一致性，因此不能把03对02解释成“加入全部可靠性门控”的收益。

所有组均为：

- 同一已选语义检查点 warmstart，`warmstart_reset_refiner:false`，保留已有精修头；新阶段各自重建相同优化器。
- 相同3,000步、原生分辨率、350个训练视图、shuffle与独立视图RNG；不恢复原阶段优化器或采样窗口。
- 冻结几何/RGB与相机，`densification:none`、`semantic_geometry_weight:0`。
- `local_teacher_kd:true`、`supervised_teacher_priority:true`、`pseudo_class_reweight_cap:3`。
- 相同教师检查点/导出模式/伪标签路径、直接二维置信度阈值（默认0.8）及类别损失权重。
- 每1,500步保存/评价，100步日志；评价全部留出视图，自动去掉继承的 `eval_max_views` 限制。

梯度路由从所选 checkpoint 的训练配置继承，默认不替换为 Rdetach。缺失该字段的旧检查点按其历史默认 true 处理。可用 `--base-config` 补充共同设置，但其 manifest、refiner架构和显式梯度路由必须与检查点一致，否则报错。

若继承 coupled 路由，最终伪标签 KL 仍能通过精修/先验支路更新语义特征，即使直接 raw KL=0；若继承 Rdetach，它只更新精修器。两组融合之间该路径完全相同。本文不把“raw pseudo权重0”描述成所有教师到原生场路径均已关闭。

## 2. 生成方法

先决定一个语义学生检查点和一个固定教师导出，再生成配置。下面的 detached 路径仅是调用示例，不代表已选出胜者；请替换为实际选定的检查点与完整伪标签目录。

```bash
uv run python scripts/make_h2_configs.py \
  --warmstart runs/strong_semantic_detached/step_008000.pt \
  --pseudo-dir artifacts/pseudo_selected \
  --output-dir configs/generated_h2_selected \
  --runs-root runs/h2_selected
```

若希望继承当时保存的完整共同配置，可加：

```text
--base-config runs/strong_semantic_detached/experiment_config.yaml
```

若仅在导出完成前准备配置，可加 `--allow-pending-pseudo`。这只允许尚无 provenance 的路径；存在但不完整/冲突的 provenance 仍会报错。训练时依然执行完整伪标签校验，不能使用未完成导出。

脚本默认要求350训练视图，并验证现有伪标签元数据覆盖全部训练视图。为避免重复读取大批概率文件，生成阶段只做元数据检查；训练入口会再次检查完整文件散列。脚本拒绝覆盖已有配置/计划，也拒绝使用已经存在的实验输出目录。选中检查点以CPU memory-map读取，不加载GPU、不改权重。

输出包含四份YAML和 `h2_plan.json`。计划记录继承路由、实验预算和**尚未执行**的命令，不冒充实验回执。第一条命令使用 `scripts/run_experiment.py` 生成不可变源码快照，其余命令通过 `--source-snapshot` 复用第一组快照。先让第一组建立快照，再启动其他组；不要让四组各自截取不同的开发中源码。

例如生成目录内计划将提供以下形式的命令：

```bash
uv run python scripts/run_experiment.py configs/generated_h2_selected/00_gt_continuation.yaml
uv run python scripts/run_experiment.py configs/generated_h2_selected/01_teacher_no_fusion.yaml --source-snapshot runs/h2_selected/00_gt_continuation/source_snapshot
```

有效配置、源码与输入来源由既有 `run_experiment.py` 回执负责记录；教师输入使用既有伪标签 provenance 链并由训练入口核验。生成器不重新创建另一套模型/数据散列回执。固定伪标签目录在整个四组实验期间不可重新导出覆盖；目前运行回执本身没有单独复制伪标签 provenance，因此还应保留该原始目录及其完整元数据。

## 3. 精确预算与GT-only控制的意义

对当前 manifest、view sampler seed=42，3,000步的实际独立shuffle序列包含：

| 数量 | 当前值 |
|---|---:|
| 训练视图 | 350（259有标签，91无标签） |
| 有标签步骤 | 2,215 |
| 无标签步骤 | 785 |
| 每视图出现次数 | 8或9 |
| 每个融合组的融合重算次数 | 15 |
| 实际进入后续loss的目标批次 | 14 |

生成器会针对继承的 seed 和 manifest 重新计算这些数值，其实现已与实际训练采样器核对。GT-only组也遍历350视图；无标签步骤没有伪标签监督，但仍有同样的残差正则。coupled时该正则可能更新原生语义场，Rdetach时只影响精修器，所有组采用同一路由。不能把此组与之前259标签专用的3,000步续训当作同一监督预算。

融合每200步在该步优化之后产生新目标，复用至下一次重算；第3,000步末生成的目标没有后续优化步骤。因此15次重算不能写成15个已用于学习的独立批次。一次随机4096点、最多四邻近视图、不同视图支持至少2；目标重用200次不是200份新观测。91个无标签视图的补充信息有限，不能预言所有组都有正收益。

## 4. 必须报告的模型指标

所有指标来自同一检查点和同一原始留出相机，不把教师对真实照片的分数混入学生相机输入渲染结果。

| 类别 | 最少报告 |
|---|---|
| 最终语义输出 | 五类/前景mIoU、五个IoU；索precision/recall；背景→索FP和索→背景FN；现有2px边界F1 |
| 原生语义渲染 | 相同的五类/前景/各类IoU及索precision/recall、混淆计数，与最终结果分列 |
| RGB隔离 | PSNR/SSIM/LPIPS；冻结几何/RGB后应与warmstart一致 |
| 资源与预算 | 实际高斯数、3k总耗时、峰值显存、融合次数及学生/教师来源 |
| 配对增量 | 03−02、02−01、01−00，分别按1.5k与3k同一步比较 |

主要终点预先固定为3k结果；1.5k只作过程诊断。保留逐视图最终/原生混淆矩阵，按相同视图配对描述差异；整体IoU由汇总混淆矩阵计算，不能换成逐图IoU简单平均。像素高度相关，不以数千万像素作为独立样本。重复种子仅对有价值的关键比较再做，不靠验证集反复筛选超参制造正结果。

如果03只改善最终mask而原生场没有改善，要明确说明；如果raw提升而final退化，报告权衡，不能宣称联合目标同时提高。原生渲染对二维区域标签的IoU不是三维测量真值。

## 5. 接受率分布如何审计

现有训练日志可直接提供：`fused_reliable_points`、`fusion_teacher_by_class`、`fusion_accepted_by_class`、`fusion_supervised_conflicts`，以及最终教师路径的 `pseudo_refiner_pixels` / `pseudo_refiner_loss`。

有一项日志时序需要特别处理：第200/400/...步先对旧融合目标算loss/冲突，再重算新目标并刷新 `fused_reliable_points`。这些行上的接受类别计数与新总数可能来自不同批次。使用第 **300、500、...、2900** 步的行，每个实际参与训练的目标批次取一次，避免混批和把重复目标当独立观测；生成计划已列出这些日志步数。

对固定范围和投影范围分别报告：

1. 每批候选4096点中，融合后权重为正的数量及比例；14批的中位数、范围和分布，不只报告最后一批。
2. 教师目标与人工保护后接受数量按五类分布；冲突拒绝比例及索/背景接受比。某类接近0时明确标出，不能由总体高接受率推断该类获得监督。
3. 使用相同随机样本/相机顺序比较03与02，报告接受数量减少是否主要落在索边界、背景或高投影方差区域。
4. 二维final教师目标也报告按预测类coverage/error与按GT类coverage，避免只看总 `pseudo_refiner_pixels`；从固定导出的 `train_confidence_calibration.json` 读取，不用验证标签训练校准器。

以下信息**当前日志尚未提供**：各门控原因的分别拒绝数、权重分位数、跨批次唯一高斯覆盖、样本投影方差与GT边界距离、实际多视图KD标量。若需将收益归因于“更准确的选择”而非“更少的监督量”，应在固定训练探针上离线重放同一证据，保存候选ID、权重和门控信息；不要声称这些诊断已经测得。仅有03优于02的结果，最多说明整套协方差范围/质量规则的增量，不能自动分离采样范围与拒绝阈值的作用。

## 6. 阈值与噪声诊断不从验证集选择

在生成/运行前锁定：直接二维教师阈值默认0.8；融合内部教师阈值0.65、最大投影标准差6px、至少2个不同训练视图；稳定人工票据至少2次且纯度≥0.8；最终边界F1继续使用现有原生2px容差。这些内部阈值由固定源码快照决定，生成器没有额外偷偷修改。

若需要在0.65/0.8/0.9之间选直接伪标签阈值，只使用已导出的训练标签coverage/error诊断，并在任何H2验证评分前确定一个值、固定全部相关组。它是训练集内诊断，有乐观偏差，不应当作留出概率校准。不能观察哪组验证索IoU最高后再为该组调整阈值。

可选的低成本噪声诊断只在预先固定的训练相机/候选点上进行，独立于3k模型选型：

- 在**480px融合网格**上，预设0/1/2px的水平与竖直伪标签平移，分别量化接受率和训练标签一致性变化。使用概率/有效区的内存副本，不覆盖正式导出；这模拟投影错位，不声称模拟所有相机误差。
- 另作预设5%/10%的类别冲突压力测试，区分单视图冲突和多视图一致但错误的教师噪声。后者可能通过一致性门控，必须如实报告这一局限。
- 训练标签边界使用预先约定的1/3/5px原生带宽作诊断分层；正式评分仍固定2px边界协议。不要用验证图选带宽或寻找最有利的边界定义。

这些诊断只检验选择机制的反应，不能替代真实留出渲染指标。若03没有超过02，或收益完全伴随接受数量/有效监督质量变化，应报告对应负结果或进一步做固定接受数量的分析；不预设投影协方差一定优于固定范围。
