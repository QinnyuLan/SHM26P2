# Prepared 硬标签与原图软概率回投：固定 CPU 诊断

本轮只检查一个可能的训练目标不一致：训练用最近邻去畸变后的硬类别，交付用 pinhole 软概率双线性映回原图再 argmax。正确像素中心也不使两种离散运算互逆。此项不是重跑 corner/Mip、不是相机校正，不改变任何标签、模型或已选 E。

固定原 legacy manifest、已完成 `cross_renderer_authority_v1` 的 H3 S 缓存和原 H3 22bc…来源。259 个有标签 TRAIN 名称排序后取 `floor(i*258/15)`：002、021、041、059、079、100、118、137、156、176、200、220、241、259、278、300。只读取这些 TRAIN 的 prepared mask/valid、原始 annotation 和 S；不读取真实 RGB、VAL、教师缓存或检查点张量，不加载模型，不渲染、不优化、不用 GPU。

复制该概率采集使用的冻结 `bridge_rgs` 包，严格复用其 `official_evaluate.distortion_render_grid(...legacy_mixed_v1)` 和官方 LabelMe rasterizer。得到的 K/尺寸必须与 cached S 的 native 网格相同；若需要额外 overscan 则拒绝，不自行填充。记部署映射为 W：当前预测为 `argmax W(S)`，往返标签为 `Y_RT=argmax W(onehot(Y_prepared))`。one-hot 的无效/255位置置零，但不因此允许其参与评分；最低类别 ID 打破概率并列，与原 argmax 相同。

共同支持固定为：原图 GT 已知，且 W 每个严格正权的四邻插值 tap 都在 native 网格内、valid>0、类别已知。零权 tap 即便越界也不影响支持；不使用容差把极小正权 tap 忽略。无效/未知不会被计为背景，也不腐蚀细索。报告全部原图已知像素数、剔除数与支持比例；所有 mIoU 是这个诊断支持内的数值，不冒充官方完整原图分数。

每视角及 pooled 统计：Y_RT≠Y0、当前错误、二者交集、虽标签不一致但当前预测正确的像素数；按 GT 五类分组，保存三份完整 CM（当前、往返标签、仅纠正交集的 oracle）。oracle 只在“当前错误且目标不一致”的像素替换为 Y0，其他位置完全不变；报告其 mIoU 增量，这是该特定集合的乐观修复量，不是模型精度上限或部署算法。

边界描述固定为每类二值原图标签的7×7方核膨胀减腐蚀（切比雪夫半径3），图框复制；每类边界带及其补集都在同一共同支持上保存计数/CM。该带只作描述，不选像素训练、不调整半径。补充视图等权比例/增量与 pooled CM 分开记录。没有按结果改变阈值、样本或追加损失；本次不设采用门，也不因数学非交换成立就放行训练。可选 CE 梯度支线未实施。

准备阶段核验已有 completed/natural-exit0 采集链及独立审计，先对 S、16份原标注、prepared mask/valid、manifest、uv.lock 和源计算 SHA 并冻结；这一阶段会读取目标文件字节做哈希，但不解码标签或加载概率数组。唯一执行只用冻结包，来源/输入前后复核。CPU 内限180秒、外限240秒、一次运行，无失败重试；所有报告写数据盘新目录。合成测试使用 `-p no:cacheprovider`，不能污染冻结源码。

本证据来自已经参与模型拟合的 TRAIN。交集不等于原因，即便 oracle 增量明显，也不能证明相同模型、固定训练预算可以实现，更不能推出新视角或 E 的收益。标签往返差异亦不证明 raw 约79%与 final 约95%的差距来自边界。未来如考虑匹配实验，应保持相同 W、输出网格和有效支持，仅比较往返标签与原标签监督，并保留未继续训练的端点；这仍是常规工程目标对齐，不是新的三维语义机制。
